## 独立接口脚本

`tests/phase2-api.mjs` 使用 Node 内置 fetch/assert，无额外依赖，不导入后端实现。仅允许访问本地地址，使用随机 qa_ 测试账号，不删除已有数据，不保存密码、cookie 或 CSRF token。

在未消耗限流额度的新隔离测试服务上按顺序运行：

```powershell
$env:TEST_BASE_URL = 'http://127.0.0.1:3001'
$env:TEST_ORIGIN = 'http://127.0.0.1:5173'
$env:TEST_ENV_FILE = 'C:\Users\26425\AI-Work\realtime-message-board\backend\.env.test'
node tests/phase2-api.mjs
node tests/phase2-db-security.mjs
node tests/phase2-rate-limits.mjs
```

结果记录分别为 `tests/phase2-api-results.json`（15/15）、`tests/phase2-db-results.json`（5/5）、`tests/phase2-rate-results.json`（3/3）。各脚本遇到首个失败即停止，未运行项不得标记通过。DB 脚本仅通过后端注册独立 QA 用户，再修改该新用户的状态/会话有效期验证鉴权；不修改已有用户。测试账号留存用于追溯。

限流脚本运行后该测试进程已耗尽限流额度，下一轮完整测试应先重启专用 3001 服务。浏览器验证使用 3000，不受该测试进程额度影响。

## 契约审查提醒

- `/api/health` 成功不代表数据库可用，必须检查 `/api/ready` 并取得真实数据库证据。
- 公开注册和登录同样要求 Origin；前端代理与允许 Origin 必须一致。
- `/auth/session` 会轮换 CSRF；多标签页需要按契约刷新令牌后最多重试一次。
- 注册每 IP 每小时 5 次、登录每 IP 15 分钟 20 次。测试应使用独立服务和可控数据，避免与手工预览争用额度；不能为了测试改变生产默认值。
- 管理端尚未实现时返回 404 只表示未实现，不构成管理员权限验证通过。
