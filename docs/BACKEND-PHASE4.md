## 数据库与一致性

真实开发库已应用 `002_comments_and_direct_messages.sql`，新增 comments、comment_idempotency_keys、dm_conversations、dm_messages、dm_idempotency_keys、dm_events。原公开事件表只扩展允许 comment.created 和 comment.deleted；私聊事件使用独立表和独立游标。

评论与帖子共用公开事件事务锁，保证内容和事件一起提交。私聊另有事务锁，保证会话创建/发送、幂等键和私聊事件一起提交、序号与提交顺序一致。双方用户 ID 规范排序及数据库唯一约束避免重复会话。

评论、私信都按创建时间和 ID 倒序游标分页，时间游标保留 PostgreSQL 微秒精度。会话列表按创建时间和 ID 稳定分页，并提供 updatedAt 与最后消息预览；前端可以按近期活动重新展示。私聊首次快照返回该用户可见事件水位，重连使用 `/dm/events` 补拉。

## 权限和实时失效

所有私聊查询、写入和订阅均检查有效登录、活跃账号及服务端参与者关系。非参与者访问指定会话统一返回 404；未登录返回 401。私信幂等键按发送用户隔离，摘要包含目标会话，不能跨会话重放。

私聊 SSE 每次取事件前重新验证会话，并在持有用户/会话锁期间发送已提交事件。退出、改密或禁用提交后不会再发送新的私聊内容；通常约 500ms 内发送 `auth.expired` 并关闭连接。网络已发送的数据不能撤回，前端在退出/切号时同步清空私聊缓存。

对方禁用时返回 `403 RECIPIENT_UNAVAILABLE`，前端只提示对方不可接收私信，不退出本人登录。本人禁用仍返回 `403 ACCOUNT_DISABLED`。该区分已同步到接口契约并通知前端。

公开评论事件：comment.created `{comment}`、comment.deleted `{commentId,messageId,deletedAt}`。私聊事件：conversation.created `{conversationId}`、dm.message.created `{conversationId,message}`。两套事件 ID 不可混用。
