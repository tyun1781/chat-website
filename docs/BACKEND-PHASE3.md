# 后端第三阶段：核心留言与实时同步

日期：2026-11-17（Asia/Shanghai）。本阶段按原 API-CONTRACT.md 实现核心留言，不改变既定请求和响应格式。

## 已完成接口

- `GET /api/messages`：公开查询，默认 20 条、最多 100 条；按创建时间和 ID 倒序进行游标分页；隐藏已删除留言；同一 REPEATABLE READ 数据库快照返回列表和事件水位。
- `POST /api/messages`：登录、Origin 和 CSRF 校验；正文统一换行并去首尾空白，1～500 个 Unicode 码点；要求 UUID 格式 Idempotency-Key。
- `DELETE /api/messages/:id`：仅作者本人可删除；软删除；本人重复删除返回 204，不重复产生事件。
- `GET /api/messages/events`：公开按事件游标补拉，默认 100 条、最多 500 条；空结果保持原游标。
- `GET /api/events`：公开 SSE；优先使用 Last-Event-ID，后备使用 after；从持久化事件顺序重放并持续跟进；15 秒心跳、3 秒重连提示。未来游标发送 sync.reset，提示 invalid_cursor。

## 一致性和权限

新增留言、幂等记录和新增事件在同一事务提交；删除和删除事件也在同一事务提交。统一事务级 advisory lock 保护事件序号分配和提交顺序。SSE 每 500 毫秒读取已提交持久化事件，因此不会推送事务回滚的内容，也没有内存订阅衔接造成的丢失窗口。

同用户同幂等键和同规范化正文重放返回原留言、200 和 Idempotency-Replayed；不同正文或已删除留言返回 409。同键重放不额外占用发言额度。新发言默认每用户每分钟 10 次、每 IP 每分钟 30 次。

列表分页游标编码时间保留数据库微秒精度，避免 JavaScript Date 毫秒精度造成分页重复或遗漏；前端应原样传回游标。公开作者仅包含 ID 和发布时昵称快照，不泄漏用户名、密码或状态。事件 ID 全程保留十进制字符串。

SSE 对慢消费者断开连接，以便客户端从已处理游标重新补拉；退出应用时主动关闭实时连接。当前最多 200 个同时实时连接，达到上限返回 503。事件和幂等记录当前不自动清理。
